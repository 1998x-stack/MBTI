# MBTI 版本演进路线图

> **V2.1 交付记录（2026-11-03）**：已基于 develop 完成 PersonaQuest V2.1 并通过 [PR #1](https://github.com/1998x-stack/MBTI/pull/1) 合并至 main。已修复截断题库（通过新的完整 12 题唯一数据源替代）、重复计分竞态（显式下一题）、评分逻辑、16 角色图片绑定和响应式 UI；自动化完成 Node 单元测试及 Playwright 14/14。版本 V2.2–V3.0 尚属规划，未实现。分支安排请以 README 为准。


## 长期分支策略

- `main`：保留历史兼容入口，后续迁移必须经 PR；不直接删除用户代码。
- `v1` / `v2`：已归档的版本快照，原则上不继续追加功能。
- `develop`：从 V2 快照出发的集成分支；新功能走 `feat/*` 与 PR。
- `release/v2.x` 或 Git tag：**仅在对应阶段真正完成并验收后创建**，不得将空分支视为已实现版本。

## V2.1 — 正确性修复与测试基线（第一优先级）

- 阻止连点重复计分与多个计时器并发跳题；提供明确的 answered 状态。
- 先修复 `question.js` 在第 12 题中途截断导致的语法不完整；再从页面分离正式题库，建立单一数据源，明确 8 题与 12 题的迁移策略。
- 实现纯函数评分器：逐轴得分、平局/无效输入处理、幂等、重算与可追踪的答题记录。
- 修正分享失败路径、未完成测评的结果屏可见性、页面重启与进度状态。
- 引入 Vitest/Jest 或 Node 内置测试、Playwright E2E、lint/check CI（依实际构建方式选择）。
- 验收：连点 100 次只计入一次；相同答案序列重复计算结果完全一致；跨轴题量不出现被错误解释为同可信度的结论；所有 16 类型映射不缺失。

## V2.2 — 数据模型与评分引擎

- 统一 `Question`/`Option`/`Dimension`/`TypeProfile` JSON Schema 或 TypeScript 类型。
- 题库独立于视图和动态特效；建立数据校验、版本号、题目 ID、内容/授权元数据。
- 将 UI 采集、答案存储、评分计算、结果解释彻底分离。
- 研究每个维度的覆盖率和题项效度，显示中性描述与不确定性，避免未经验证的概率与精确置信度。
- 验收：错误数据被拒绝，题目排序变更不影响相同 ID 的答案重放；所有评分有黄金测试。

## V2.3 — 体验与可访问性

- 合并 V1 动物角色视觉资源与 V2 情境互动体验，避免重复图片。
- 提供返回上一题、修改答案、断点恢复、移动端交互、深色模式和结果分享。
- 全键盘导航、screen reader 语义、明确焦点、对比度、reduce-motion。
- 验收：手机与桌面端关键流程 E2E；无阻塞级可访问性问题。

## V2.4 — 可部署与质量工程

- 构建脚本、资产指纹与缓存策略，压缩/重编码图片；剔除无引用资产（先通过引用清单确认）。
- GitHub Actions：格式/静态检查、数据 Schema、单元测试、端到端测试与产物验证。
- 清晰的内容安全策略、安全 DOM 更新、错误边界与离线降级。
- 优先本地保存，不默认上传测试答案；明确删除/分享控制。
- 验收：冷启动、首屏、交互稳定性、体积预算及部署回滚演练有可复现记录。

## V3.0 — 可信的人格探索产品（规划，未实现）

- 将娱乐性的类型探索与有研究来源的维度问卷分开呈现。
- 若引入正式心理量表，先确认许可、规范施测方式和心理测量学证据。
- 明确提示非诊断、非招聘筛选依据，允许用户质疑/修订自我描述。
- 只有取得合适数据与验证设计后，才做统计校准；不得依靠 AI 文案生成替代测量学验证。

## 建议 PR 顺序

1. `feat/v2.1-question-state-machine`
2. `feat/v2.1-single-source-data`
3. `feat/v2.1-pure-scoring-engine`
4. `test/v2.1-e2e-and-ci`
5. `feat/v2.2-question-schema`

每一个 PR 标明问题复现、设计决策、自动化验证结果、回滚方式以及修改影响范围。
