## 3. V1 静态审计

源文件：`script.js`（约 613 行）、`index.html`、`style.css`、`data/questions.json`、`data/types.json`、`assets/`、`lib/confetti.js`。

- 实际运行：`initApp` 采用内嵌 `inlineQuestions`（12 道）和 `inlineTypes`（16 类）；外部 JSON 并没有在运行时加载。
- 数据一致性：内联题库与 questions.json 一致；人格类型数据中 ESTJ 的 animalImage 与 types.json 路径不同（内联采用以 / 开头的绝对路径）。
- **P0 结果图故障**：`showResults()` 获取了 animal-image 并设置 alt，却没有设置 `animalImage.src = personality.animalImage`；动物图片将不按结果切换。
- **P1 计分边界**：四个维度分别进行 E>I、S>N、T>F、J>P 比较，平局固定选 I/N/F/P；未交代不确定性及结果稳定性。
- **P1 成就语义错误**：例如“连续5题选择独处选项”实际只判断 I 分数 > 30，未记录连续选择序列。
- **P1 可访问性**：题目选项使用可点击 div，缺少原生 button 键盘交互语义与焦点管理。
- **P1 维护/安全**：展示选项与成就时使用 innerHTML；当前源为本地静态数据，但接入远程/用户输入前必须以 textContent 或经过验证的安全渲染替代。
- **P2 数据单一来源**：inline JSON 和 JSON 文件重复，需要统一配置源；暂不删除原始数据以保证可追溯。

## 4. V2 静态审计

源文件：`v2/index.html`（约 1023 行，CSS/JS 内联）、`v2/question.js`（ES Module，独立数据文件）。

- **P0 题库断裂**：页面内置 `questions` 只有 8 道题；独立 `question.js` 声明了 12 道题，但没有被 index.html 导入。
- **P0 模块文件不完整（新增核验）**：`v2/question.js` 在第 12 题的第一个 option 对象刚开始后即到达文件末尾，缺少对象、数组与模块的闭合部分；因此该文件目前是语法不完整的草稿，不可直接作为有效 ES Module 导入。需先恢复完整题库，再考虑统一数据源。
- **P1 维度样本不平衡**：运行题库 E/I 2 道、S/N 1 道、T/F 3 道、J/P 2 道。结果的百分比是简单得分比，不是经过测量学验证的概率或置信度。
- **P0 连击竞态**：`selectOption` 没有锁定当前问题；在 500ms 延时内重复点击可重复累加分数并安排多个跳题定时器，破坏答题状态和结果。
- **P1 结果防护**：直接导航到“我的结果”时不会校验是否已完成测评，可能显示占位数据而非有效结果。
- **P1 分享降级**：剪贴板写入与 Web Share 缺少完整拒绝/不支持时的错误恢复；非安全上下文中 clipboard API 可能不存在。
- **P1 资产路径**：独立模块定义了 /images/scenarios/... 场景图片路径，而现有 v2 文件树中没有相应目录；这些字段当前没有被页面消费。
- **P2 可访问性/性能**：固定间隔创建粒子特效，CSS 的 prefers-reduced-motion 不一定停止 JS Web Animations 的粒子创建；需要统一的动效开关与清理策略。
- 优点：原生按钮、移动端 CSS、基本 keyboard focus 样式、暗色主题和较清晰的情境化题目表达。

## 5. 数据与产品定位

两版都是娱乐/自我探索性质的短问卷，**不能直接宣称心理诊断、科学测量结果、职业能力判定或医疗结论**。未来测评应注明题目来源、版权授权、适用范围、分数解释、限制与隐私处理。不要将简单百分比分数包装成科学置信度。

## 6. 合并与验收约定

1. 历史分支 v1/v2 保持快照语义；修复开发从 develop 派生 feat/*。
2. 每次功能修改应有可独立审查的 PR 和回归测试；无需为规划中的版本创建空 release 分支。
3. 先修复无效计分/跳题/资源加载，再优化 UI；UI 更漂亮不能替代正确性。
4. 只有通过数据 Schema 检验、单元测试、浏览器 E2E、可访问性检查及构建/部署验证后，才建立相应稳定 release 标签或 release 分支。
5. 初期使用静态站点部署；除非明确需要账户、多端同步、管理后台，否则避免过早添加数据库与服务器。
