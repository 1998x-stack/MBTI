# PersonaQuest V3.0 — Explainable Self-Discovery（产品需求文档 PRD）

**文档状态**：Proposed / 设计已完成、功能未实现 · 2026-11-03  
**基础版本**：main `cf5063531b3683dd9c16a71993c6f604557b2606`（V2.2，Pages 已于当日成功部署）  
**研究依据**：[`PH_HN_RESEARCH_2026.md`](./PH_HN_RESEARCH_2026.md)（真实评论、平台规范、样本局限）  
**定位边界**：娱乐与自我反思，不是心理诊断、正式测量、职业筛选或他人匹配/好坏评级。

## 1. 一句话战略

**Don't tell people who they are. Show them how their choices shaped a result.**  
**不是“给我贴上性格标签”，而是“让我看见选择、解释依据，并有权不同意”。**

这是与 16Personalities 式分类站、AI 长报告、社交关系测评的差异。核心竞争力不是量表更准（项目无相关证据），而是**信息透明、情境丰富、可质疑、有趣、无需注册且本地优先**。

### 不同比更大的三层目标（Altitude）

1. **当前任务**：把 12 题静态测评变成能完整理解、分享、质疑的一次高质量体验。
2. **更高目标**：让用户得到一个能自己验证、适合与朋友讨论的情境反思产物，而非一次性标签。
3. **长期目标**：在不暗中收集个人数据的前提下，成为用户可反复自愿使用的自我反思工具；后续路线必须由真实观察决定。

**首发聚焦第 1 层和小部分第 2 层，不提前建设第 3 层的账户、同步、社交关系网络或 AI 教练。**

## 2. 事实基线、问题与机会

### 2.1 当前已实现

- 12 个原创情境（四轴各三题）、4 选项、16 种趣味角色；题库版本 2.1.0、评分版本 2.1.0。
- `src/core/assessment.js` 纯函数评分，平局返回 null；`src/core/explanation.js` 生成答题证据和中性文本。
- 结果页显示四个维度对应的三条回答；无注册、答案 localStorage、不上传服务器。
- Web 静态架构、GitHub Pages、AVIF/WebP、自适应 UI、暗色模式与 axe/Playwright 检查。
- **未实现**：即时结果如何产生的动态示范、反事实试算、让用户反驳结论、个人反思导出、分享图片、英文完整体验与独立用户验证。

### 2.2 有证据支持的问题

1. 初见用户无法立刻区分此产品和许多 MBTI 类测试（PH/HN 源见研究文档）。
2. 当前首页强调趣味动物图片；真正的差异化解释证据埋在做完 12 题之后。
3. 现在可以**查看**证据，但不能在不修改原答题记录的情况下试验“改一道题会怎样”。
4. 当前解释是只读，不支持用户说明何时适用、何时不适用。
5. 目前仅 `zh-CN`，而 Product Hunt 面向国际用户；直接国际发布会有体验断层。
6. 当前**没有**独立于开发者的用户反馈数据；故页面好看、单元测试通过不能证明实际价值。

### 2.3 用户工作（Jobs-to-be-Done）

- **好奇探索者**：当我看到一个有趣的情境题，希望无需注册就知道系统如何解释我的答案。
- **认真思考者**：当结果让我疑惑，我希望看到是哪几道题导致了这个方向，并能试一试其他选择。
- **愿意分享的用户**：当我觉得结果有趣，我希望能分享不暴露逐题记录的结果卡，同时有权不分享。
- **技术/隐私敏感用户**：当我访问一个人格工具，我希望清楚知道它是什么、没证实什么、在哪里处理数据。
- **辅助技术用户**：当我只用键盘或屏幕阅读器时，我应完成相同核心体验而不是被视觉交互阻挡。

不允许在 UI 暗示“人格已经被 AI 客观识别”“这是你真正的人格”或“类型可判断他人值得交往/雇佣”。

## 3. Product Hunt 定位与信息层级

- 产品英文名：**PersonaQuest**
- 英文一句话：**A personality quiz that shows its work.**（38 字符以内）
- 进一步解释：**12 everyday scenarios. See the choices behind your result, challenge an answer, and keep your data on your device. No account needed.**
- 中文一句话：**12 个情境，看见选择，而不被标签定义。**
- 核心独特主张：**Explain → Challenge → Reflect**，不是“更精准预测类型”。
- 主要竞争对象：一般四字母测试站及 AI 性格长报告；**不是**关系交友平台/正式测量服务。
- 首发价格：Free，无账户与数据上传；不设早期订阅/付费墙。

### 3.1 前 90 秒信息结构

```text
0–10 s   首页：一眼看见「怎么得出结论」动效/静态可操作样例
10–30 s  一道**示例**场景：两个选择，实时展示“依据怎么变”
30–60 s  展开：题目 → 选项 → 对应方向，不显示假精确置信度
60–90 s  CTA：开始真实 12 题 / 继续查看说明
          ↓
3–4 min  完成全部真实题目（待实测）
          ↓
结果页   画像 + 四轴证据 + 可选“换一题试试” + 个人反思
          ↓
可选      分享无敏感答案的卡片 / 本地保存 / 删除
```

**重要：演示模式绝不能被误认为已经计算出用户的完整类型。** 首屏示例是解释工作方式，正式分型仅使用 12 道题。

## 4. 信息架构和页面规格

### S0 Landing / Preview

**区块**：导航（首页、如何计算、隐私、English/中文） → 核心主张 → 即时互动演示 → 明确的 12 题完整体验入口 → 三条可信边界 → FAQ。  
**按钮**：`Try a one-question demo`、`Take the 12-scenario quiz`。无注册、无需留邮箱。  
**状态**：未交互、选择示例回答、展示说明、切换回答、开始完整问卷、恢复已保存进度。  
**可访问性**：演示的选项用原生 radio；变化时有非强制 aria-live 文案；跳过演示可到真实测评。

### S1 Question Flow

维持 V2.2 的题库和评分实现，避免产品化重写引入科学性表述。只补充语言选择、明确当前题次、用户主动恢复、完整键盘与读屏支持。用户完成前不显示确定的四字母类型。

### S2 Result: Summary → Evidence → Challenge

结果页分层：

1. **Summary**：趣味角色、四字母组合或 Mixed、明确的娱乐/非诊断说明。
2. **Why this result**：四轴的**选择数量**和左右**计分权重**（必须清楚分别标注；不可把 3 道选择数当成权重分数）。
3. **Evidence**：每轴三道题，每条显示所选选项及对应计分方向。
4. **Try another answer（反事实）**：在沙盒中更改一道题，显示改变的维度、权重变化、是否导致类型变化。默认不保存。
5. **Your interpretation**：用户对一句具体描述选择“符合 / 不符合 / 看情境”，可输入一句私人反思（非必填）。
6. **Share / Export**：生成不含逐题答案的图片卡；原始详细答案导出需独立选择并强调隐私。

#### 核心效果：反事实差异视图

```text
原来你选择：提前安排计划（J +2）
试试换成：当天随性决定（P +2）
本轴加权差值：D_old → D_new
整体四字母组合：仅当真实按权重越过分界才改变
【撤销试验】 【仅将此项正式应用到我的答案】
```

所有数字必须来自 `evaluateAnswers()`，不得由 UI 或 AI 生成猜测；平局显示 Mixed，不绕过现有平局规则。

### S3 Reflection / Notes

本地记录结构围绕一个**具体句子**，不收集心理健康、财务、关系等额外敏感问题。用户可修改、删除、导出。文本是用户自己写的，不做人格分析或暗中远传。没有自动“每周你应该复测”的提示。

### S4 Share Card

默认图卡只包含：产品名、用户主动选择的角色或类型、1 句明确的趣味探索文案、一个**通用主页 URL**。不包含姓名、手机号、答题序列、自由文本、位置、心理概率或网络跟踪 ID。可选择只分享“我试了一个有趣的情境探索”而不公开类型。分享前必须有可见预览。

### S5 Trust / Methodology

不藏在最底部的免责声明：

- 这不是官方 MBTI，12 道原创题没有已验证的可靠性或预测效度。
- 展示的方向、分数与证据只来自你当次所选选项。
- 允许你得出与结果不同的自我理解。
- 不上传答题内容；如何删除 localStorage；何时信息会随分享公开。
- 未来若增加 AI 文本生成功能，必须标记为生成式解释、默认关闭、不允许虚构证据、审查模型输入及成本；首发不做。

### 6.1 反事实引擎接口（建议）

```ts
type CounterfactualResult = {
  questionId: string;
  originalOptionId: string | null;
  candidateOptionId: string;
  before: AssessmentResult;  // evaluateAnswers 的完整结果
  after: AssessmentResult;   // 仅内存里替换一个答案后的结果
  changedAxes: AxisId[];
  typeChanged: boolean;
  committed: false;
};

function simulateAnswerChange(
  bank: Question[],
  answers: Record<string, string>,
  questionId: string,
  candidateOptionId: string
): CounterfactualResult;
```

需要保证：永远不修改传入的 `answers`；不改变 `localStorage`；针对未回答、无效题号/选项、平局、已完成都能一致处理；在“正式应用”时才通过现有持久化路径写入。

### 6.2 反思数据契约（建议）

```json
{
  "schemaVersion": "1.0.0",
  "bankVersion": "2.1.0",
  "entries": [
    {
      "evidenceQuestionId": "q01",
      "assessmentClaimId": "EI-summary",
      "verdict": "depends",
      "note": "只在熟悉的群体里比较主动"
    }
  ]
}
```

字段不引入姓名、手机号、地理位置、诊断、联系人，`note` 可以为空；存储前限制字数、渲染只用 `textContent`，用户一键删除。浏览器本地密钥按 Schema 版本隔离，导出需显式点击，不提供自动云同步。

### 6.3 双语约束

中文是当前规范源；英文翻译需要人工评审语义等价。必须保持题目与选项 ID、轴方向和权重一致，但相同 ID 不等于两种语言的回答心理意义必然相同。不能凭双语一致的代码测试宣称跨文化效度。

### 6.4 产品分析与隐私

**默认不添加第三方行为采集。** 初期以明确知情的可用性测试收集任务时间、界面问题、参与者主动反馈，不记录原答案。若引入生产分析，必须新增独立同意、分类事件（只允许匿名计数、不记录答案/文本/IP/类型）、明确保留周期、删除控制和数据保护审查；未经同意时不开启分析。

### 6.5 性能与无障碍

- 站点仍使用静态 GitHub Pages，避免不必要的后端。
- 保持现有 AVIF/WebP 构建；结果页额外功能不得使重要交互卡顿。
- 以 Core Web Vitals 良好体验阈值为长期目标，不能用单次 Lighthouse 自评分替代真实用户第 75 百分位数据。
- axe/Playwright 仅提供自动覆盖；真实 NVDA、VoiceOver、TalkBack 人工核验才可以评价读屏体验。
- `prefers-reduced-motion`、键盘、语义 `radio`、返回焦点、高对比和 400% 放大是发布硬门槛。

## 7. 分阶段实施（每阶段单独 PR，不扩大目标）

| 阶段 | 工程工单 | 交付与验收 | 依赖/退出条件 |
| --- | --- | --- | --- |
| P0 | UX-90 / CORE-CF | 首屏互动示例 + 纯反事实模拟 | 内部数据不变式与 12×4 黄金测试、样例不会产生结果 |
| P1 | EVIDENCE-01 / REFLECT-01 | 维度计数与权重严格区分、可撤销试算、用户对描述的意见 | 结果与证据完全可追溯，无法暗中上传个人输入 |

不要将阶段数量当 KPI；如果 P0 的真实用户价值不成立，就停止扩展并修正，而不是添加更多题库/AI。

## 8. 成功定义及发布门槛

**北极星**：用户在首次体验中能独立说清“一条结论来源于哪些选择”，并完成一次自愿的证据查看或反思。  
不能仅看点击率，因为按钮被强引导也会出现点击。需要**理解题测试**：让用户解释“结果告诉你什么/没有告诉你什么”。

### 8.1 实验目标（待验证，不是现有数据）

- **首次理解**：≥80% 测试者明确知道这不是临床诊断或确定人格归类。
- **15 秒定位**：≥60% 能解释“它与普通人格测试有什么不同”。
- **90 秒价值**：≥70% 在无需工作人员帮助的情况下完成首屏示例、看到证据变化。
- **完整任务**：≥85% 自愿测试者在 ≤5 分钟内完成测评与结果查看；记录中途退出原因。
- **可解释性**：≥80% 能回答“哪些答案影响这个维度”“数字不是人格概率”。
- **隐私理解**：≥90% 理解分享图卡不会默认包含逐题回答。
- **技术**：桌面/移动 E2E 全绿，schema/data/counterfactual golden 测试全绿；上线后实际 URL 所有静态资源正常。
- **无障碍**：不宣称自动扫描即 WCAG 认证；至少完成关键任务的人工 NVDA + VoiceOver + 手机读屏核验。
- **产品诚实性**：没有未经验证的科学性、职业预测、关系匹配分数等宣传。

样本 12–20 人**足以发现明显 UX 问题，但不足以证明统计显著性或大众偏好**。需要记录任务失败的具体位置、定性反例以及不同语言体验差异。

## 9. 风险登记与停止条件

| 风险 | 等级 | 触发信号 | 对策 |
| --- | --- | --- | --- |
| 标签限制自我认识 | 高 | 用户把结果当永久定义或能力评判 | 更显眼地展示反证与情境变化，禁止“真实人格”文案 |
| 自己做的短题库却声称官方/准确 | 高 | 网站/PH 文案出现“scientifically accurate” | 发布阻断、文案扫描 + 人工复核 |
| 二选一导致偏见 | 高 | 用户将标签用于评价朋友/同事 | 不提供关系优劣/筛选结论，允许不公开类型 |
| 隐私泄露 | 高 | 分享包含答案、反思笔记或识别码 | 隐私快照测试、逐字段白名单 |
| 初期 Aha 不成立 | 高 | 90 秒示例难懂或无价值 | 优先改造文案和样例，不继续扩大需求 |
| 跨语言语义偏差 | 中高 | 中文/英文问题理解不同 | 双语内容审查，不宣称测量等价 |
| 深功能拖慢站点 | 中 | 资源预算或 Web Vitals 回退 | 禁止首屏重型可视化/大依赖 |
| 社交功能变成关系评价 | 高 | 被要求出“最佳伴侣/员工”评分 | 拒绝该功能方向，改成自愿对话建议 |

## 10. 完成定义（DoD）

- 每条需求可追溯到真实用户工作/明确假设，而非“功能越多越好”。
- 每一条结果显示都能追溯至选项与评分规则；人工可复算。
- 实际目标用户参与自愿可用性测试，用户是否理解得到外部证明。
- 通过跨浏览器、无障碍人工和自动测试，修复 P0/P1 缺陷。
- 上线资源和 HTTPS 在正式站点验证，Product Hunt 首发的素材与实际产品一致。
- 发布门槛未达标时，诚实报告未达标的指标，不通过虚假投票/虚构评价冲榜。
